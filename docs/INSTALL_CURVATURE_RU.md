# Smart Skin 0.0.24-p08e1n3 — установка

Используйте единственный установочный ZIP из успешного Windows GitHub Actions run для указанного final commit. Архив исходников и test-report не являются установщиком.

1. Закройте Rhino. Полностью распакуйте install ZIP в отдельную папку. В её корне должны находиться `INSTALL.cmd`, `UNINSTALL.cmd`, `manifest.json`, `build-info.txt` и каталог `net48`.
2. Запустите корневой `INSTALL.cmd`. Установка не требует прав администратора и не запрещает административный токен текущего пользователя. Не нужно менять UAC, учётную запись или runtime Rhino.
3. Дождитесь `SMARTSKIN_INSTALL PASS`. Rhino автоматически не запускается.
4. Откройте Rhino и выполните `SmartSurfaceVersion`: версия должна быть `0.0.24-p08e1n3`, commit — из `build-info.txt` и manifest проверенного CI-пакета. Эта известная команда также загружает плагин перед запуском новой диагностики.

Условия: Windows x64, Rhino 8.21+ в ветке8, .NET Framework4.8. Плагин имеет target net48; фактическая среда Rhino может быть .NET8. Это разные характеристики. Геометрический движок использует встроенный Rhino CPython3.9 с закреплёнными NumPy1.26.4, SciPy1.13.1, mpmath1.3.0. Их первоначальная подготовка выполняется Rhino и может потребовать сеть.

## Проверенный установочный контракт

- Пользовательская регистрация HKCU, фиксированный GUID, `%LOCALAPPDATA%\SmartSkin\Rhino8\current`
- При обновлении заменяются известные файлы Smart Skin; чужие файлы и панели сохраняются
- Временные `.staging-*`/`.previous-*` нужны только для восстановления при ошибке; после успешной операции удаляются
- Ни наличие HKLM-регистрации, ни административный токен сами по себе не блокируют установку
- HKLM-регистрации, их права, общий Rhino UI/layout и системные настройки не меняются
- Ошибка после начала замены восстанавливает предыдущие файлы и пользовательскую регистрацию; если восстановление не завершилось, журнал явно сообщает об оставшихся резервных данных

## Удаление

Закройте Rhino и запустите `UNINSTALL.cmd` из установочного пакета. Он снимает активную регистрацию Smart Skin и удаляет известные файлы плагина, сохраняя чужие файлы. Это настоящее удаление, а не возврат на предыдущую версию.

## Ошибочный запуск исходников

`SOURCE_LAYOUT` означает, что запущен `scripts/INSTALL.cmd` из source checkout либо неполного каталога. Ничего не устанавливается и не пересобирается. Нужен корневой INSTALL.cmd именно установочного CI ZIP; не копируйте отдельный CMD между версиями.

## Границы проверки

Windows CI проверяет actual CMD → Windows PowerShell5.1 → настоящий установочный script, пути с пробелами/не-ASCII, контексты токена, обновление/удаление и восстановление на изолированных целях. Статус относится только к успешному exact-SHA run, указанному при доставке. Native Rhino loading/UI/Join и реальная геометрия в этом CI не запускаются: **NOT VERIFIED** до целевого полевого теста. F3 не использует прежний PARTIAL-результат как разрешение на добавление. Исключение относится только к двум явно определённым верхним угловым точкам; конечные участки исходных границ и новые стыки должны пройти проверки. Численные и mock-проверки не заменяют полевой сценарий Rhino. Устанавливайте только пакет, для которого отдельно подтверждены успешный exact-SHA CI, artifact ID и hash.

## Исправление F4

Исправлено чтение локальных направлений у исходного угла: направление пространственного ребра и направление trim на родительской поверхности проверяются в своих базисах. Это устраняет ложный отказ `Native owner frame is not orthogonal`. Допуски примыканий и исходная геометрия сохранены. Установка и загрузка F3 уже подтверждены пользователем; работа исправления F4 в Rhino требует нового полевого теста.

## Взаимодействие F5

После выбора исходных рёбер дождитесь завершения этапов построения и проверок. Окно показывает этап, прошедшее время и лимит; до READY рычаги недоступны. Исправлено обновление списка рычагов после первого построения. В READY выберите U/V-направляющую и рычаг в окне модели либо через списки Guide/Handle, затем меняйте слайдер. Enter / Space / правая кнопка принимают проверенный результат, Esc или закрытие окна отменяют его. Исходники не меняются. Работа нового выбора в настоящем Rhino требует полевого теста; списки остаются запасным способом выбора.

## Исправление F6 и проверка скорости

Исправлен ложный `OWNER_SCREEN_STALE`: запросы bounding box и solid-состояния заполняют служебные данные Brep и меняют его сериализацию. Теперь подготовка этих данных предшествует выдаче отпечатка; последующие изменения геометрии, исходников или запроса по-прежнему блокируют принятие. При другом расхождении журнал укажет компонент.

Начальный нейтральный запрос использует уже проверенные поверхности и направляющие без повторного построения и полной повторной численной проверки. Проверка native-владельцев выполняется заново. Обработка событий ограничена частотой, но отмена и сроки проверяются на каждом контрольном шаге. В журнале появились счётчики и время обработки событий. Измеренное ускорение численной нейтральной стадии на тестовом Linux: 15.22 → 1.63 секунды; фактическое время Rhino требует полевого замера.

В READY выберите редактируемую направляющую `U row 1`–`U row 8` или `V profile 1`–`V profile 5`. Восемь структурных стыков доступны для осмотра и не имеют рычагов. Для плеча: `V profile 1` либо `V profile 5`, затем `Upper shoulder lift`. Если выбран структурный стык, неактивный слайдер ожидаем.

## Восстановление слайдера F7

После отклонённого изменения можно снова выбрать меньшее значение слайдера. В F6 восстановление предыдущей формы отзывает native-подтверждение и ошибочно блокирует сам слайдер; F7 разделяет запрос следующего изменения и разрешение принять форму. Перед повторной попыткой проверяются исходники и допуски, затем выполняются все обычные проверки. Отклонённая попытка не принимается автоматически.

История команды показывает запрошенный рычаг/значение, применённую ревизию либо причину возврата. До завершения проверок видна предыдущая проверенная форма. Для изменения середины продольного профиля выбирайте центральную `V profile 3`, а не верхнюю `U row 1`. Это локальные воздействия на разные участки. Конструктор исходной формы и диапазоны рычагов в F7 не менялись.

Левый щелчок выбора направляющей/рычага не должен одновременно принимать результат. После выбора подтвердите отдельным Enter / Space / правым щелчком. Добавлена защита от передачи того же события выбора в цикл подтверждения; по снимку нельзя установить, происходило ли это в вашем случае.

При первом READY автоматически выбрана редактируемая U/V-направляющая. Структурные стыки помечены `read-only` и остаются доступны для осмотра; их осознанный выбор сохраняется.

## N2: направление первого Match

Это диагностическая сборка. Обычный `SmartSurfaceBuild` сохранён и ещё не заменён новым алгоритмом. Для текущего теста после установки запустите **`SmartSkinNativeCompare`** из командной строки и выберите исходный замкнутый набор naked Brep edges.

Команда сохраняет исходный вариант EdgeSrf и выполняет только первый Match на двух независимых копиях: ReverseMatchDirection=false и true. Второго последовательного Match нет. Журнал показывает соответствие концов и результат отдельно по каждой из четырёх сторон, чтобы отличить ошибку направления от перемещения соседних границ.

В просмотре Next переключает исходный EdgeSrf и полученные варианты. Название показывает, какой вариант отображается. Enter/Done/Esc закрывает просмотр и освобождает временные кандидаты. Объекты документа не добавляются и не заменяются. В N3 полный отчёт сохраняется в TXT по инструкции ниже; снимок выбранного варианта помогает сопоставить измерения с формой. Подробности геометрического опыта — `P08E1N2_MATCH_CORRESPONDENCE.md`. Успешный ответ Match сам по себе не подтверждает G2; обе попытки могут оказаться непригодными.

## N3: полный TXT-отчёт

Запустите `SmartSkinNativeCompare` на исходном замкнутом наборе рёбер. Геометрические операции и просмотр такие же, как в N2. После завершения, отмены или ошибки появится выбор папки для отчёта. Выберите папку: полный журнал Smart Skin будет сохранён в UTF-8 TXT с уникальным именем; итоговый путь появится в командной строке. Существующий файл не перезаписывается.

Отчёт собирается непосредственно во время работы команды, поэтому размер истории Rhino его не ограничивает. Он включает параметры входа, варианты, измерения по сторонам и итоговую очистку. Хорошая форма в предварительном просмотре сама по себе не подтверждает G2.

Если выбор папки отменён или файл не удалось записать, выполните `SmartSkinNativeReport`, чтобы повторить сохранение последнего завершённого отчёта без пересчёта. Буфер хранится до закрытия Rhino либо следующего завершённого диагностического запуска. Отчёт не отправляется автоматически. Передайте полученный TXT для разбора; при необходимости приложите снимок с названием выбранного варианта. Уже обрезанную историю предыдущего запуска восстановить этим способом нельзя: нужен новый запуск N3.
