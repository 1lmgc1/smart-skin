# Smart Skin 0.0.19-p08e1f5 — установка

Используйте единственный установочный ZIP из успешного Windows GitHub Actions run для указанного final commit. Архив исходников и test-report не являются установщиком.

1. Закройте Rhino. Полностью распакуйте install ZIP в отдельную папку. В её корне должны находиться `INSTALL.cmd`, `UNINSTALL.cmd`, `manifest.json`, `build-info.txt` и каталог `net48`.
2. Запустите корневой `INSTALL.cmd`. Установка не требует прав администратора и не запрещает административный токен текущего пользователя. Не нужно менять UAC, учётную запись или runtime Rhino.
3. Дождитесь `SMARTSKIN_INSTALL PASS`. Rhino автоматически не запускается.
4. Откройте Rhino и выполните `SmartSurfaceVersion`: версия должна быть `0.0.19-p08e1f5`, commit — из `build-info.txt` и manifest проверенного CI-пакета.

Условия: Windows x64, Rhino 8.21+ в ветке8, .NET Framework4.8. Плагин имеет target net48; фактическая среда Rhino может быть .NET8. Это разные характеристики. Геометрический движок использует встроенный Rhino CPython3.9 с закреплёнными NumPy1.26.4, SciPy1.13.1, mpmath1.3.0. Их первоначальная подготовка выполняется Rhino и может потребовать сеть.

## Проверенный установочный контракт

- Пользовательская регистрация HKCU, фиксированный GUID, `%LOCALAPPDATA%\SmartSkin\Rhino8\current`
- При обновлении заменяются известные файлы Smart Skin; чужие файлы и панели сохраняются
- Временные `.staging-*`/`.previous-*` нужны только для восстановления при ошибке; после успешной операции удаляются
- Ни наличие HKLM-регистрации, ни административный токен сами по себе не блокируют установку
- HKLM-регистрации, их права, общий Rhino UI/layout и системные настройки не меняются
- Ошибка после начала замены восстанавливает предыдущие файлы и пользовательскую регистрацию; если восстановление не завершилось, журнал явно сообщает об оставшихся резервных данных

## Удаление

Закройте Rhino и запустите `UNINSTALL.cmd` из установочного пакета. Он снимает активную регистрацию Smart Skin и удаляет известные файлы плагина, сохраняя чужие файлы. Это настоящее удаление, а не возврат на предыдущую версию.

## Ошибочный запуск исходников

`SOURCE_LAYOUT` означает, что запущен `scripts/INSTALL.cmd` из source checkout либо неполного каталога. Ничего не устанавливается и не пересобирается. Нужен корневой INSTALL.cmd именно установочного CI ZIP; не копируйте отдельный CMD между версиями.

## Границы проверки

Windows CI проверяет actual CMD → Windows PowerShell5.1 → настоящий установочный script, пути с пробелами/не-ASCII, контексты токена, обновление/удаление и восстановление на изолированных целях. Статус относится только к успешному exact-SHA run, указанному при доставке. Native Rhino loading/UI/Join и реальная геометрия в этом CI не запускаются: **NOT VERIFIED** до целевого полевого теста. F3 не использует прежний PARTIAL-результат как разрешение на добавление. Исключение относится только к двум явно определённым верхним угловым точкам; конечные участки исходных границ и новые стыки должны пройти проверки. Численные и mock-проверки не заменяют полевой сценарий Rhino. Устанавливайте только пакет, для которого отдельно подтверждены успешный exact-SHA CI, artifact ID и hash.

## Исправление F4

Исправлено чтение локальных направлений у исходного угла: направление пространственного ребра и направление trim на родительской поверхности проверяются в своих базисах. Это устраняет ложный отказ `Native owner frame is not orthogonal`. Допуски примыканий и исходная геометрия сохранены. Установка и загрузка F3 уже подтверждены пользователем; работа исправления F4 в Rhino требует нового полевого теста.

## Взаимодействие F5

После выбора исходных рёбер дождитесь завершения этапов построения и проверок. Окно показывает этап, прошедшее время и лимит; до READY рычаги недоступны. Исправлено обновление списка рычагов после первого построения. В READY выберите U/V-направляющую и рычаг в окне модели либо через списки Guide/Handle, затем меняйте слайдер. Enter / Space / правая кнопка принимают проверенный результат, Esc или закрытие окна отменяют его. Исходники не меняются. Работа нового выбора в настоящем Rhino требует полевого теста; списки остаются запасным способом выбора.
